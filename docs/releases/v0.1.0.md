# Auto-Test v0.1.0 首发

- 支持 Playwright UI 自动化、API 功能测试和性能测试。结构化 UI 回放、API 和性能测试无需配置模型，自然语言 UI 测试需配置租户模型。
- 多租户 Web 工作台支持管理需求、环境、用例和测试数据，运行测试套件和每周计划，查看执行报告与缺陷复测结果。
- MCP 支持触发测试、查询运行状态和报告。支持 Sampling 的客户端可从代码生成待人工审核的 API 或 UI 用例草稿。

## 安装包

| 平台 | 发布文件 | 安装方式 |
| --- | --- | --- |
| Linux amd64 | `Auto-Test-linux-amd64.tar.gz` | 用 `docker load -i` 导入镜像，按部署指南配置 Docker Compose v2。 |
| Windows x64 | `Auto-Test-windows-x64-setup.exe` | 运行安装程序，从开始菜单启动。 |
| macOS arm64（Apple Silicon） | `Auto-Test-macos-arm64.dmg` | 挂载 DMG，将 `Auto-Test.app` 拖入 `Applications`。 |

可用随发布提供的 `SHA256SUMS.txt` 校验下载文件。

## 首次部署

桌面版在 Auto-Test 窗口内显示工作台。首次打开即可创建工作区并注册管理员。应用随安装包提供界面渲染组件、Python 和 Playwright Chromium。启动后在工作台签发 worker 令牌并按部署说明配置。[桌面安装与首次配置](https://github.com/DamonZS/Auto-Test/blob/v0.1.0/docs/deployment/README.md)

Windows 的开始菜单、窗口和托盘使用 Auto-Test 图标，macOS 可从 Dock 或菜单栏恢复窗口。关闭桌面窗口会收起应用，托盘菜单的「退出 Auto-Test」会停止本地服务和 worker。Windows 开始菜单的 `Stop Auto-Test` 也会显示停止结果。

Linux 服务端通过 `-provision-user` 初始化工作区管理员，后续通过网页登录。[服务端部署与旧库迁移](https://github.com/DamonZS/Auto-Test/blob/v0.1.0/docs/deployment/README.md#linux-服务端)

## 签名与客户端限制

- 桌面包供内部验收。Windows 安装程序尚未签名，macOS 应用尚未完成 Developer ID 签名与公证，安装或启动可能受 SmartScreen 或 Gatekeeper 限制。
- MCP 用例生成要求客户端声明 Sampling 能力并支持 Streamable HTTP 的 SSE 请求与回包。各客户端尚未逐项联调。不支持 Sampling 的客户端仍可调用普通测试工具，用例生成不会回退到平台模型。[MCP Sampling 接入说明](https://github.com/DamonZS/Auto-Test/blob/main/docs/api/mcp-sampling.md)
