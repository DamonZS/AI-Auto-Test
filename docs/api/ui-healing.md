# UI 定位自愈

结构化 UI 用例的角色与无障碍名称定位失效时，执行端可使用工作区模型在当前作用域的可见同角色候选中选择一次。执行端验证目标唯一且可见，按原动作重试，然后继续执行已保存的断言。用例跑完且恢复动作后的断言通过时，执行端才上报自愈成功。执行证据保留尝试结果。

原有执行完成接口可以携带 `self_healed: true` 和 `patch`。`patch.step_seq` 从 1 开始计数，`old_selector` 与 `new_selector` 是步骤的原无障碍名称与候选名称。补丁随执行结果保存。服务端关联领取任务时的用例版本，供审批比较。

`GET /api/patches` 返回租户内补丁及对应的用例。`POST /api/patches/{id}/decide` 由工作区所有者提交 `approve` 或 `reject`。批准时，服务端核对执行时的用例版本、步骤、原名称与当前版本一致，再保存新修订、更新用例和补丁状态。旧版来源或发生冲突时返回 `409`。拒绝只更新补丁状态。

数据迁移采用新增列。升级前纳入 SQLite 例行备份。旧执行及补丁保留展示，缺少执行时用例版本的补丁可以拒绝。迁移验证使用隔离 SQLite 数据库。
