# 企业测试工作台

## 准入与审核

所有产物绑定已有的租户、项目和版本。同租户的版本必须属于所选项目。模板按以下顺序展示，允许同一版本保留多份日报与同行评审记录。

| 类型 | 提审必填内容 |
| --- | --- |
| `test_application` 测试申请 | 申请人、测试范围、需求或变更说明、期望开始和完成日期 |
| `test_plan` 测试计划 | 目标与范围、测试环境、负责人、计划起止日期、策略与里程碑 |
| `entrance_checklist` 准入检查单 | 申请已批准、需求资料经评审、开发自测通过、环境及数据就绪、测试资源就绪、用例评审通过、冒烟通过 |
| `peer_review` 同行评审记录 | 评审对象、参会人、评审日期、评审结论、问题与整改安排（无问题可填「无」） |
| `daily_report` 测试日报 | 报告日期、进展、阻塞问题（无阻塞可填「无」）、下一步安排 |
| `exit_checklist` 准出检查单 | 执行记录已归档、执行和覆盖已达标、高严重度缺陷已处理、复测与回归完成、遗留项已确认、报告材料齐备 |
| `test_report` 测试总结报告 | 测试范围与环境、遗留缺陷与风险（无风险可填「无」）、测试结论 |

测试申请、计划、准入、日报、准出、总结采用企业 E2E 输出模板的通用字段。同行评审参考企业同行评审报告。检查单每项填写 `pass` 或 `fail` 和证据文本，全部 `pass` 且有证据方可提审。清单用于签核测试准入与准出，执行队列沿用已有入口。模板目录返回字段键、类型、标签和检查项，Vue 直接用目录渲染编辑器。日期用 `YYYY-MM-DD`，结束日期须不早于开始日期。

`draft → in_review → approved | rejected`。草稿允许未填完。提审校验必填、日期顺序和清单，缺失项通过 `422` 的 `missing_sections` 返回。审核人和驳回意见是决定时的必填项。驳回后保存会回到草稿，清空本轮签核和统计，允许重新提审。审核中和已批准的正文冻结。每次成功写入递增 `revision`，修改和审核必须携带已读取的修订号。状态或修订号冲突返回 `409`。提审、批准和驳回与审计日志同事务写入。

所有产物均需人工批准才能导出 UTF-8 HTML。工作台使用统一的 Web 会话和工作区成员校验。只读成员可查看与导出已批准产物，提交和签核需要工作区编辑权限。

审核请求发送 `action`、`revision` 和 `note`（驳回必填）。批准和驳回使用 `authenticatedActor(r)` 的用户名签核。只有 `authenticatedActor(r)` 为空的旧测试夹具使用请求中的 `reviewer`。响应中的 `reviewer` 和 `reviewed_at` 用于签核详情与导出，审计使用相同的认证主体。

## 报告质量和统计

当前版本已导入的语句、行和分支覆盖率随报告提审一并冻结。

日报与总结报告在提审时冻结该项目、版本的累计平台数据。有效用例数为项目下已批准的用例数。执行状态按每个有效用例在该版本的最近一条已结束执行计算，先比较结束时间，再比较入库顺序。`passed` / `failed` 分别计通过 / 失败，其余终态计阻塞。测试起止时间为参与统计的记录中最早入队和最晚完成的 UTC 时间，无执行时为空。排队和运行中的记录不参与执行统计。

需求覆盖率以项目需求为分母，以关联了已批准用例的项目需求为已覆盖。执行率为已执行数除以有效用例数，通过率为通过数除以已执行数，分母为零时取 `0`。缺陷按 `bugs.run_id` 所关联的版本统计总数、优先级和严重度。优先级和严重度去首尾空白并转大写，已关闭与已驳回的记录从遗留缺陷中排除。手工缺陷、跨版本复现目前可能缺少该版本的执行关联，由报告作者在遗留风险中补充。日报日期是报告标识，统计为提审时的累计进度。

总结报告沿用 `report-quality.md` 的字段与完整度要求。测试范围与环境、遗留风险、结论由人工填写，统计由平台生成。`review_signoff` 对应产物 `status`、`reviewer` 与 `reviewed_at`，其中 `in_review` 对应 `pending`。报告风险为 P0/P1、缺陷优先级存在 P0/P1 或结论含「上线」时，冻结快照标记 `requires_human_review`。工作台对所有产物执行人工批准门禁，覆盖 `workbench_catalog.py` 的高风险复核约束。目录用于流程产物录入和审核，静态 AI 入口目录继续用于 Agent 侧定义。

## 注册与验证

1. 存储代理在 `store.Open` 初始化阶段调用 `MigrateWorkbench(db)`，处理错误后再启动服务。SQLite 迁移可重复执行。
2. `(*Server).Routes` 在返回 `cors(mux)` 前调用 `s.registerWorkbench(mux)`。注册函数使用现有 `s.tenant`。
3. `App.vue` 在 `NAV` 注册 `{ key: 'workbench', label: '企业流程', comp: WorkbenchView }`。视图用共享 `api.post` 提审和签核，通过 `error.detail` 读取 `422` 明细，通过 `api.download` 携带会话和租户头下载 HTML。
4. 验收覆盖七类模板、失败准入、驳回重提、审批冻结、租户与版本边界、基于实际执行的报告快照及 HTML 下载。运行 `go test ./internal/api -run TestWorkbench -count=1`、`go test ./...` 和 Web 构建。
